# 題目一：Ackermann Function

## 解題說明

這題要用兩種方法來算 Ackermann Function，一種是遞迴，一種是非遞迴。主程式會一直讀入 m 和 n，然後印出 A(m,n) 的答案。

Ackermann Function 的規則有三種情況：

| 條件 | A(m,n) 的值 |
|------|-------------|
| m = 0 | n + 1 |
| m > 0 而且 n = 0 | A(m-1, 1) |
| m > 0 而且 n > 0 | A(m-1, A(m, n-1)) |

## 解題策略

### 遞迴版本

遞迴版本我是照著規則一條一條寫成 if。

1. 先看 m 是不是 0。如果是，這就是最簡單的情況，直接回傳 n + 1，不用再呼叫自己。
2. 如果 m 大於 0 但 n 是 0，就改算 a(m-1, 1)，m 會少一。
3. 如果 m 和 n 都大於 0，就要先算裡面的 a(m, n-1)，把算出來的答案當成外面那一層的 n，再去算 a(m-1, 那個答案)。
4. 每呼叫一次，m 和 n 都會往比較小的方向走，所以最後一定會碰到 m 等於 0 而停下來。
5. 主程式用 while (cin >> m >> n) 一直讀資料，讀到沒有資料為止，這樣一次可以測很多組。

### 非遞迴版本

非遞迴版本的想法是，遞迴其實就是電腦幫我們把「還沒做完的事」疊起來，那我們自己疊就好了。

1. 我自己用一個陣列 st 當成堆疊，再用 top 記錄現在疊到第幾個位置，就像疊盤子一樣，最後放上去的最先拿下來。
2. 堆疊裡面只放還沒處理的 m。n 只有一個數字，所以用一個變數一直更新就好。
3. 每次從堆疊拿出最上面的 m，然後看三種情況：
   - m 是 0：n 加 1，這一步就做完了。
   - n 是 0：把 m-1 放進堆疊，然後把 n 改成 1。
   - 其他情況：先放 m-1，再放 m，然後 n 減 1。這樣下一圈會先處理 m，等它做完才輪到 m-1，剛好跟遞迴的順序一樣。
4. 堆疊空了就代表全部做完，這時候的 n 就是答案。
5. 每次算新的一組資料之前，要先把 top 設成 0，不然上一組的東西會影響這一組。

## 程式實作

### 遞迴程式

```cpp
#include <iostream>

using namespace std;

int a(int m, int n) {
	if (m == 0) return n + 1;
	else if (m > 0 && n == 0) return a(m - 1, 1);
	else if (m > 0 && n > 0) return a(m - 1, a(m, n - 1));
}

int main()
{
	int m, n;
	while (cin >> m >> n) {
		cout << a(m, n) << endl;
	}
	return 0;
}
```

### 非遞迴程式

```cpp
#include <iostream>
using namespace std;

int st[10000000];
int top = 0;

void push(int x) {
	st[top++] = x;
}

int pop() {
	return st[--top];
}

int ackermann(int m, int n) {
	top = 0;
	push(m);
	while (top > 0) {
		m = pop();
		if (m == 0) {
			n++;
		}
		else if (n == 0) {
			push(m - 1);
			n = 1;
		}
		else {
			push(m - 1);
			push(m);
			n--;
		}
	}
	return n;
}

int main()
{
	int m, n;
	while (cin >> m >> n) {
		cout << ackermann(m, n) << endl;
	}
	return 0;
}
```

### 非遞迴執行過程，以 A(1,1) 為例

| 步驟 | 拿出來的 m | 這時的 n | 做了什麼 | 堆疊裡剩下（左邊是底部） | 新的 n |
|------|-----------|---------|----------|------------------------|--------|
| 開始 | 無 | 1 | 放入 1 | 1 | 1 |
| 1 | 1 | 1 | 放入 0 和 1，n 減 1 | 0 1 | 0 |
| 2 | 1 | 0 | 放入 0，n 變 1 | 0 0 | 1 |
| 3 | 0 | 1 | n 加 1 | 0 | 2 |
| 4 | 0 | 2 | n 加 1 | 空的 | 3 |

堆疊空了，答案是 3，和遞迴版本算出來的 A(1,1) = 3 一樣。

## 效能分析

### 遞迴版本

1. 時間：Ackermann Function 長得非常快，呼叫的次數很難用 n、n 平方這些常見的式子來說。看 m 的大小就知道：
   - m = 1 的時候，答案是 n + 2，呼叫次數跟 n 差不多。
   - m = 2 的時候，答案是 2n + 3，呼叫次數大約是 n 的平方。
   - m = 3 的時候，答案是 2 的 (n+3) 次方再減 3，呼叫次數是指數成長。
   - m = 4 以後就會暴增，一般電腦根本算不完。
2. 空間：遞迴會用到系統的 Call Stack，最深的時候層數跟答案的大小差不多，所以很快就會用完。
3. 輸入太大的話，不是 Stack Overflow 程式當掉，就是答案超過 int 的範圍而算錯。

### 非遞迴版本

1. 時間：和遞迴版本一樣。我們只是把電腦做的事改成自己做，要做的步驟一步都沒有少，所以一樣很慢。
2. 空間：實際用到的堆疊深度和遞迴版本差不多，不過我開了固定大小的陣列，一千萬個 int 大約是 40 MB，不管輸入大小都會先占著這些空間。
3. 跟遞迴版本比起來：
   - 陣列放在全域，不占系統的 Call Stack，所以不會那麼快 Stack Overflow，可以撐到一千萬層。
   - 每一層只存一個 int，比遞迴每層要存一整個 stack frame 小很多。
   - 缺點是容量固定，超過就會出錯，而且我沒有檢查。
4. n 和答案還是 int，太大一樣會溢位。

1. 遞迴和非遞迴兩種寫法都可以算出正確答案，而且每一筆測試的輸出都一樣。

## 申論及開發報告

### 這題用到的資料結構是堆疊

這題最重要的資料結構就是堆疊（Stack）。堆疊的特色是後進先出，最後放進去的東西會最先被拿出來，就像一疊盤子，你一定是從最上面那個開始拿。

遞迴的時候，電腦其實就在用堆疊。每呼叫一次函式，電腦就會在 Call Stack 上多放一個 stack frame，裡面記著這次的 m、n，還有做完之後要回到哪裡。函式結束就把這個 frame 拿掉。因為最後呼叫的函式一定最先結束，所以剛好符合後進先出。

以 a(1,1) 為例，遞迴會這樣展開：

```text
a(1,1) 要先算 a(0, a(1,0))
a(1,0) 要先算 a(0,1)，得到 2
a(0,2) 得到 3
```

在算裡面的 a(1,0) 的時候，外面的 a(0, 還沒算好) 還在等，這些等待中的呼叫都疊在堆疊裡。m 和 n 越大，等待的東西就疊越多，最後就爆掉了。

### 為什麼非遞迴也用堆疊

我在想非遞迴的版本時，發現不能只用普通的 for 或 while 迴圈，因為這個函數需要記住很多還沒做完的事，順序還不能亂。能夠幫我記住這些事又保持順序的，就是堆疊。

而且我發現外層的呼叫其實只有 m 不一樣，第二個參數要等裡面算完才知道，所以堆疊只要存 m 就夠了，n 用一個變數一直更新。這樣每一格只要存一個整數，比電腦存整個 stack frame 省很多空間。

### 用陣列做堆疊

堆疊有很多種做法。我選擇用陣列，因為陣列在記憶體裡是連續的，用索引 top 就能直接找到最上面的位置，放進去和拿出來都只要一行程式，速度很快。

- push 就是 st[top++] = x，先放進去，top 再加 1。
- pop 就是 st[--top]，top 先減 1，再把那格的值拿出來。
- 堆疊空不空，只要看 top 是不是 0。

另外也可以用鏈結串列（Linked List）做堆疊，那樣就不會有容量上限，每次 push 再多要一塊記憶體就好。不過每個節點都要多存一個指標，而且要用 new 和 delete，比較麻煩，所以我還是選陣列。

### 陣列堆疊和 STL stack 的比較

| 項目 | 自己用陣列做 | STL 的 stack |
|------|-------------|--------------|
| 容量 | 固定，要先決定大小 | 會自己變大 |
| 邊界檢查 | 要自己寫 | 不會越界，用法正確的話 |
| 程式碼長度 | 要自己寫 push 和 pop | 直接用就好 |
| 空間 | 一開始就占滿，這題約 40 MB | 用多少占多少 |
| 學到的東西 | 能了解堆疊裡面怎麼運作 | 比較方便 |

這份作業的重點是了解遞迴和堆疊的關係，所以我選擇自己寫陣列版本。

### 遞迴和非遞迴的比較

| 項目 | 遞迴 | 非遞迴 |
|------|------|--------|
| 堆疊在哪裡 | 系統的 Call Stack | 我自己宣告的全域陣列 |
| 好不好讀 | 跟題目的規則幾乎一樣，很好懂 | 要懂堆疊怎麼模擬才看得懂 |
| 每層存什麼 | 整個 stack frame | 只有一個 int |
| 容量 | 受系統限制，容易 Stack Overflow | 固定一千萬格，超過會出錯 |
| 速度 | 一樣很慢 | 一樣很慢 |

### 兩種寫法的優缺點

遞迴的優點是程式短，而且和規則幾乎一樣，不容易寫錯。缺點是層數太多就會當掉，而且同樣的 a(m,n) 會被重複算很多次。

非遞迴的優點是不怕系統堆疊太小，而且每層用的空間比較少。缺點是邏輯比較難想，要自己顧 top 和 n，陣列大小也是固定的，沒有檢查邊界就可能出錯，另外用全域變數的話，也不適合多個程式同時使用。

### 還可以怎麼改進

1. 可以把算過的答案記下來，不要重複算，這叫記憶化。不過 m 和 n 一大，記憶體也會不夠。
2. 可以把 int 改成 long long，讓答案晚一點溢位，不過還是治標不治本。
3. 可以在 push 裡面加上檢查，如果 top 快超過陣列大小就停下來，或是改用 STL 的 stack。

# 題目二：冪集（Power Set）

## 解題說明

這題要輸入一個集合，然後把它所有的子集合都印出來，這些子集合合起來就叫冪集。

如果集合有 n 個元素，就會有 2 的 n 次方個子集合，空集合和集合本身也都算。

例如集合 {A, B, C}，它的冪集是：

```text
{}, {A}, {B}, {C}, {A,B}, {A,C}, {B,C}, {A,B,C}
```

輸入的格式是第一行先給元素的個數 n，接下來給 n 個元素，每個元素都當成字串。

## 解題策略

我把每個元素都想成要做一個選擇，要放進子集合，或是不放。全部的元素都選完，就是一個子集合。

1. 我寫了一個遞迴函式 pow，它有五個參數：
   - A：原本的集合。
   - s：現在正在組合的子集合。
   - i：現在輪到第幾個元素。
   - n：集合有幾個元素。
   - t：s 裡面現在放了幾個元素。
2. 如果 i 等於 n，代表所有元素都選完了，這時候 s 的前 t 個就是一個子集合，直接印出來。
3. 如果還沒選完，就先處理不放 A[i] 的情況，直接去看下一個元素。
4. 接著處理要放的情況，把 A[i] 放到 s[t]，t 加 1，再去看下一個元素。
5. s 只有一個陣列，沒有每次都開新的。因為我們只看前 t 個，後面的不管它，所以不用特別把東西清掉。

整個過程就像畫一棵樹，每個元素分成選和不選兩條路，走到最下面就是一個子集合。

## 程式實作

```cpp
#include<iostream>
#include <string>
using namespace std;

void pow(string A[], string s[], int i, int n, int t) {    // A[]:集合 s[]:子集 i:目前處理到A[i] n:集合大小 t:子集大小
	if (i == n) 
	{
		cout << "{";
		for (int j = 0; j < t; j++) 
		{
			cout << s[j];
			if (j != t - 1) cout << ",";
		}
		cout << "}" << endl;
		return;
	}
	pow(A, s, i + 1, n, t);        
	s[t] = A[i];                  
	pow(A, s, i + 1, n, t + 1);    
}

int main()
{
	int n;
	cin >> n;
	string* A = new string[n];
	string* s = new string[n];
	for (int i = 0; i < n; i++)
	{
		cin >> A[i];
	}
	cout << "冪集為:" << endl;
	pow(A, s, 0, n, 0);

	delete[] A;
	delete[] s;
	return 0;
}
```

## 程式說明

### 陣列 s 和變數 t

s 的大小是 n，不過只有前 t 格是有用的。

- 不選元素的時候，t 不變，後面的格子就當作沒有東西。
- 選元素的時候，把元素放到 s[t]，t 加 1。

所以每一種情況都用同一個 s，不用為每個子集合都開一個新的陣列。

### 展開過程，以集合 {A,B} 為例

```text
pow 從 i=0, t=0 開始
  不選 A，進入 i=1, t=0
    不選 B，進入 i=2, t=0，印出 {}
    選 B，進入 i=2, t=1，印出 {B}
  選 A，進入 i=1, t=1
    不選 B，進入 i=2, t=1，印出 {A}
    選 B，進入 i=2, t=2，印出 {A,B}
```

所以輸出的順序是 {}、{B}、{A}、{A,B}。

## 效能分析

設集合有 n 個元素。

1. 時間：
   - 遞迴樹最底下有 2 的 n 次方個葉節點，每個葉節點就是一個子集合。
   - 每個子集合最多要印 n 個元素，所以全部加起來是 O(n × 2^n)。
2. 空間：
   - 遞迴最深只會有 n + 1 層，所以 Call Stack 是 O(n)。
   - 陣列 A 和 s 各 n 格，也是 O(n)。
   - 全部加起來還是 O(n)。因為子集合是邊產生邊印出來，沒有全部存起來，所以不會到 2 的 n 次方那麼大。

1. 程式可以把所有子集合都印出來，數量也和 2 的 n 次方一樣。

## 申論及開發報告

### 這題用到的資料結構

**一、陣列和動態配置**

集合的元素放在陣列 A 裡面，因為要等使用者輸入 n 才知道要放幾個，所以我用 new 在執行的時候才決定大小，用完再用 delete[] 還給電腦，這樣就不會浪費，也不會有記憶體洩漏。

**二、s 和 t 其實是一個堆疊**

仔細看 s 和 t 的用法，會發現它就是一個用陣列做的堆疊：

- 選元素的時候，s[t] = A[i]，t 加 1，就是 push。
- 回到上一層的時候，t 會自動變回原本的值，就像 pop 一樣，不用另外寫。

這是因為每一層遞迴的 t 都是各自一份，回到上一層，上一層的 t 還是原來的數字，後面多放的元素自然就不算了。這樣遞迴和堆疊就搭配得很好。

**三、遞迴的過程是一棵二元樹**

每個節點都會分成兩個子節點，一個是不選，一個是選，樹的高度是 n，最底下剛好有 2 的 n 次方個葉節點，每個葉節點就是一個子集合。程式走訪這棵樹的方式是先走到底，再回頭走另一邊，這就是深度優先走訪。因為我先寫不選，所以第一個印出來的一定是空集合。

**四、Call Stack**

遞迴的時候，系統同時最多只會有 n + 1 層函式在等，所以空間很省。如果把全部 2 的 n 次方個子集合都存起來，記憶體會大很多。

### 為什麼用遞迴

冪集有一個很好用的特性，n 個元素的冪集，可以拆成兩半：不含第一個元素的子集合，和含第一個元素的子集合，這兩半都是 n-1 個元素的冪集問題。這和遞迴把大問題變成小問題的想法一樣。

如果用迴圈，就需要知道 n 才能寫幾層迴圈，不夠彈性。遞迴就不用管 n 是多少。

### 和其他寫法的比較

| 寫法 | 用的資料結構 | 時間 | 額外空間 | 特色 |
|------|------------|------|---------|------|
| 我的遞迴，選或不選 | 陣列和 Call Stack | O(n × 2^n) | O(n) | 程式短，邏輯清楚 |
| 位元遮罩 | 整數 | O(n × 2^n) | O(1) | 用 0 到 2^n - 1 的二進位表示子集合，但 n 受整數大小限制 |
| 一個一個加入並複製 | vector 裡面放 vector | O(n × 2^n) | O(n × 2^n) | 好懂，但要全部存起來，很占記憶體 |

我的寫法不用存全部結果，也不會被整數的位元數限制，所以比較適合邊算邊印。

### 優缺點

優點：

- 想法簡單，只要決定這個元素選或不選。
- 只用一個暫存陣列，不需要清除。
- 空間只要 O(n)，很省。

缺點：

- 子集合的數量本來就是 2 的 n 次方，輸出一定很多，這是題目本身的問題。
- 遞迴呼叫要花一些時間，n 大的時候會比位元遮罩慢一點。
- 如果輸入的元素有重複，會印出重複的子集合，要先排序再加判斷才能解決。

# 作業總結

這次做了兩題，都和遞迴有關，不過遞迴的用法不一樣。

## 題目一：Ackermann Function

用遞迴和非遞迴兩種方法來寫。非遞迴版本用全域陣列 st 和 push、pop 自己做一個堆疊，我從中學到遞迴其實就是系統在幫我們用堆疊，也知道這個函數為什麼會讓堆疊爆掉。

## 題目二：冪集

把每個元素看成選或不選，用遞迴走過一棵二元樹，產生所有子集合。陣列 s 加上 t 的用法就像一個堆疊。

# 兩題比較

| 題目 | 主要方法 | 時間 | 空間 | 用到的資料結構 |
|------|---------|------|------|---------------|
| 題目一 Ackermann | 遞迴，或用堆疊模擬 | 成長非常快，兩種寫法一樣 | 跟堆疊深度差不多 | 堆疊，系統的或陣列做的 |
| 題目二 Power Set | 遞迴，選或不選 | O(n × 2^n) | O(n) | 動態陣列、堆疊、二元樹 |

兩題都有用到 Call Stack，差別是：

- Ackermann 用遞迴來算出一個數字，要注意的是堆疊會長得多快。
- Power Set 用遞迴來列出所有可能，要注意的是那棵選或不選的樹，還有暫存陣列怎麼重複使用。

做完這兩題，我覺得遞迴不只是一種寫法，它和堆疊、樹這些資料結構都有很深的關係。
